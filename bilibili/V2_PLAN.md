# Windows v2.0 实施记录

需求来源：用户提供的《Windows 视频下载器 v2.0 —— 全面重构开发需求》。本次仅重构 Windows；安卓保持既有版本与功能。

产品：原生 Qt 桌面下载工具，面向希望粘贴链接保存完整媒体的用户。核心对象为链接、真实下载任务、本地媒体记录和软件版本。入口为下载页的主动粘贴；平台自动识别，不在输入尚未完成时启动，不监听系统剪贴板。成功路径是粘贴、下载、完整性校验、入库、内置预览；失败保留输入并提供登录、重试和日志。

界面：成熟工具的紧凑三页布局，1050×720，固定窄侧栏，下载 / 我的视频 / 软件更新。浅灰背景、白色面板、深色正文、玫红强调。使用 Qt Widgets、系统字体、共享主题与原生窗口；不引入 Web 前端框架。常用内容优先，不把调试信息或内部实现说明放在主页面。不增加第四个设置页。

主要风险：粘贴重复触发；未完整下载的文件被导入；缩略图阻塞 GUI；媒体解码失败无反馈；目录修改导致旧记录丢失；更新卡在零进度；安装失败破坏旧程序。对应使用规范化任务键、独立下载进程与发布前校验、虚拟化模型及有界异步缩略图、Qt Multimedia 与外部播放器备用入口、多目录 SQLite 库、真实字节回调及范围续传、独立更新助手备份和恢复。

实施顺序：

1. 已审查：app.py、downloader.py、parallel_http.py、Bilibili / Douyin 适配器、图文导出、浏览器账号读取、程序内网页登录、路径与设置、更新核心、安装及发布脚本。
2. 原下载内核保持最佳可用音画、完整性校验、同格式备用节点。调整临时目录与最终成品发布，保留图文和实况。
3. 增加任务队列、主动粘贴事件、设置面板、用户目录内的 SQLite 视频库、历史导入、缺失文件检测、缓存缩略图及本地播放器。
4. 更新页展示真实版本及 Release Notes、字节 / 速度 / ETA；后台检查只在发现新版时提醒。支持取消、重试、校验、独立安装、重启和恢复。
5. 使用隔离输出目录、本地 HTTP Release 服务器和模拟安装器验证要求的 20 条场景；不为测试发布正式版本或删除正式资源。补充真实媒体下载和独立 EXE 验证，产出实际交付说明与安装包。

兼容策略：保留 settings.json、WebProfile 与现有下载路径。SQLite 和缓存放到 LOCALAPPDATA/LocalVideoDownloader，移除记录使用隐藏标记，删除文件必须确认。更改输出目录仅影响后续任务，旧目录继续纳入库。数据库迁移先备份，不在安装目录保存用户数据。

原有工程根 Git 仓库与旧删除项无关，不修改；应用源码单独发布工作区仍为 bilibili/build/github-project。正式 v1.0.4 安装包在 v2 验证完成前保留。

参考：[Qt Multimedia](https://doc.qt.io/qtforpython-6.11/PySide6/QtMultimedia/index.html)、[QMediaPlayer](https://doc.qt.io/qtforpython-6/PySide6/QtMultimedia/QMediaPlayer.html)、[Inno Setup 命令行](https://jrsoftware.org/ishelp/topic_setupcmdline.htm)、[安装返回码](https://jrsoftware.org/ishelp/topic_setupexitcodes.htm)。

当前阶段：实现与验收已完成，正在整理正式交付。累计 82 项单元/HTTP 检查、20 项 Qt 下载/库交互及 16 项 Qt 更新交互通过。真实独立 EXE 下载 B 站完整样例并内置播放，另经全片音画解码；抖音生日短链接真实导出全部素材。100%/150%/200% 布局检查、实际 Inno 安装器与冻结助手的原目录覆盖升级、自动启动及数据保留通过。验证中发现并修复旧版 Qt/Python 运行库遮蔽和 Windows 长路径备份问题；失败启动后的旧版恢复也已实际执行。测试没有修改正式 GitHub 发布资源；正式 v2 发布按用户先前指定的仓库进行，历史发布保留供恢复。证据与未覆盖场景见 V2_DELIVERY.md。
